## O que são Agentes de IA?

Agentes de IA são sistemas que utilizam modelos de IA (LLMs) juntamente com ferramentas externas para executar tarefas de forma autônoma.

Enquanto um LLM tradicional apenas responde perguntas com base em seu treinamento, um agente pode:

- Pesquisar na web
- Consultar bancos de dados
- Ler documentos
- Fazer cálculos
- Executar fluxos de trabalho
- Tomar decisões baseadas em contexto

Por isso, agentes são considerados sistemas compostos de IA.

### Limitação dos modelos tradicionais

Modelos de linguagem possuem limitações naturais:

- Conhecimento limitado aos dados de treinamento
- Possibilidade de alucinações
- Não possuem acesso automático a informações atualizadas
- Não conseguem executar ações externas sozinhos

Por exemplo:

**LLM tradicional:**

> "Qual é o estoque atual do produto X?"

Ele não sabe, pois essa informação não estava presente em seu treinamento.

**Agente de IA:**

1. Recebe a pergunta
2. Consulta o banco de dados da empresa
3. Obtém a informação atualizada
4. Responde corretamente

# ReAct (Reason + Act)

Um dos métodos mais importantes para construção de agentes é o padrão ReAct.

ReAct significa:

- **Reasoning (Raciocinar)**
- **Acting (Agir)**

O agente primeiro pensa sobre o problema e depois executa ações para resolvê-lo.

### Exemplo

Pergunta:

> "Qual foi a receita da empresa no último trimestre?"

Fluxo:

1. Raciocina:
    - Preciso consultar o banco financeiro.
2. Age:
    - Executa consulta SQL.
3. Analisa:
    - Recebe os resultados.
4. Responde:
    - Informa a receita ao usuário.

Esse ciclo de pensamento + ação é a base dos agentes modernos.

# Quando usar LLM e quando usar Agentes?

## Use apenas um LLM quando:

- O problema for simples
- Não precisar acessar dados externos
- Não exigir múltiplas etapas
- For apenas geração de texto

Exemplos:

- Criar resumo
- Escrever e-mails
- Gerar código simples
- Traduzir textos

---

## Use Agentes quando:

- Precisar consultar sistemas externos
- Precisar executar várias etapas
- Houver necessidade de tomada de decisão
- Precisar acessar dados atualizados

Exemplos:

- Assistente financeiro
- Suporte técnico corporativo
- Sistema de RH
- Chatbots empresariais
- Análise de documentos

---

# Tipos de Agentes de IA

## 1. Agente Reflexo Simples

É o tipo mais básico.

Funciona através de regras do tipo:

```
SE condiçãoENTÃO ação
```

### Exemplo

```
Se temperatura > 30°Ligar ar-condicionado
```

Características:

- Simples
- Rápido
- Não aprende
- Não possui memória

---

## 2. Agente Reflexo Baseado em Modelo

Possui uma representação interna do ambiente.

Além de seguir regras, ele considera o estado atual do sistema.

### Exemplo

Um robô aspirador:

- Sabe onde já limpou
- Sabe quais áreas ainda faltam

Características:

- Possui memória interna
- Considera mudanças do ambiente
- Mais inteligente que o reflexo simples

---

## 3. Agente Baseado em Metas

Possui um objetivo específico.

Ele escolhe ações que o aproximam da meta desejada.

### Exemplo

GPS:

Meta:

> Chegar ao destino.

O agente escolhe rotas que aproximam o usuário do objetivo.

Características:

- Planejamento
- Busca por objetivos
- Tomada de decisão orientada a resultados

---

## 4. Agente Baseado em Utilidade

Vai além da meta.

Ele analisa qual caminho produz o melhor resultado.

### Exemplo

Duas rotas chegam ao destino:

- Rota A: 20 minutos
- Rota B: 40 minutos

Ambas atingem a meta.

O agente escolhe a rota com maior utilidade.

Características:

- Avalia custos e benefícios
- Busca eficiência
- Compara alternativas

---

## 5. Agente de Aprendizagem

Aprende continuamente com experiência.

Seu desempenho melhora ao longo do tempo.

### Exemplo

Netflix:

- Observa filmes assistidos
- Aprende preferências
- Melhora recomendações

Outros exemplos:

- Spotify
- TikTok
- YouTube
- Sistemas antifraude

Características:

- Aprende com dados
- Adapta-se a mudanças
- Evolui continuamente

# O que é RAG?

RAG significa:

**Retrieval Augmented Generation**

(Geração Aumentada por Recuperação)

É uma técnica que permite que um LLM consulte informações externas antes de responder.

Em vez de depender apenas do treinamento do modelo, ele recupera informações relevantes e utiliza essas informações para gerar a resposta.

---

## Problema que o RAG resolve

Imagine perguntar:

> "Qual é a política de férias da minha empresa?"

Um modelo comum não sabe.

Com RAG:

1. Busca documento interno
2. Recupera conteúdo relevante
3. Envia para o modelo
4. Modelo gera resposta baseada no documento

---

# Fluxo do RAG

### 1. Usuário faz uma pergunta

```
Como funciona a política de férias?
```

### 2. Sistema converte a pergunta em vetor

Representação matemática do texto.

### 3. Busca no banco vetorial

Localiza documentos semelhantes.

### 4. Recupera contexto

Trechos relevantes são encontrados.

### 5. Envia para o LLM

O contexto recuperado é fornecido ao modelo.

### 6. Modelo responde

Resposta baseada nos dados recuperados.

---

# Banco de Dados Vetorial

É um banco especializado em armazenar embeddings.

Embeddings são representações matemáticas de textos, imagens ou documentos.

Em vez de buscar palavras exatas, ele busca significado.

---

## Exemplo

Pergunta:

```
Como solicitar férias?
```

Documento:

```
Procedimento para pedir férias.
```

Mesmo sem palavras iguais, o banco entende que possuem significado semelhante.

---

## Bancos Vetoriais Populares

- Pinecone
- Weaviate
- ChromaDB
- Qdrant
- Milvus
- FAISS

---

# Vantagens do RAG

### Dados atualizados

Não depende apenas do treinamento do modelo.

### Menos alucinações

Respostas são baseadas em fontes reais.

### Menor custo

Não exige retreinamento do modelo.

### Segurança

Pode usar documentos privados da empresa.

# MCP (Model Context Protocol)

MCP significa:

**Model Context Protocol**

É um protocolo aberto criado para padronizar a comunicação entre modelos de IA e ferramentas externas.

Pode ser comparado a uma "porta USB para IA".

---

## Problema que o MCP resolve

Antes do MCP:

Cada ferramenta precisava de uma integração específica.

Exemplo:

- Banco de dados
- CRM
- ERP
- Google Drive
- GitHub

Cada integração era construída individualmente.

---

## Com MCP

Todos os sistemas seguem um padrão único.

O agente consegue acessar diferentes ferramentas utilizando a mesma interface.

---

# O que o MCP pode conectar?

- Bancos de dados
- APIs REST
- GitHub
- Google Drive
- Notion
- Slack
- Jira
- Sistemas corporativos
- Serviços internos

---

# Estrutura MCP

### Cliente MCP

Normalmente o agente ou LLM.

### Servidor MCP

Ferramenta que fornece acesso aos recursos.

### Ferramentas

Funções disponíveis.

Exemplos:

- Consultar banco
- Criar tarefa
- Buscar documento
- Atualizar registro

---

# Exemplo de uso MCP

Usuário pergunta:

> "Quais tarefas estão atrasadas no Jira?"

Fluxo:

1. Agente entende a pergunta
2. Usa servidor MCP do Jira
3. Consulta tarefas
4. Obtém resultados
5. Responde ao usuário

# N8N

O N8N é uma plataforma de automação de fluxos de trabalho.

Ele funciona como um orquestrador que conecta aplicações, APIs e agentes de IA.

---

## O que ele permite?

- Automatizar processos
- Criar agentes
- Integrar sistemas
- Processar documentos
- Executar fluxos complexos

---

## Exemplos de integrações

- Gmail
- WhatsApp
- Slack
- Google Drive
- MongoDB
- PostgreSQL
- OpenAI
- Gemini
- GitHub

---

# Exemplo de fluxo no N8N

Receber currículo por e-mail:

1. Gmail recebe arquivo
2. N8N extrai texto
3. IA analisa currículo
4. IA gera avaliação
5. Resultado enviado ao RH

Tudo automaticamente.

---

# Bolt.new

O Bolt.new é uma ferramenta de desenvolvimento baseada em IA que gera aplicações completas através de prompts em linguagem natural.

---

## Exemplo

Prompt:

> "Crie um sistema de biblioteca com Spring Boot e React."

A ferramenta pode gerar:

- Front-end
- Back-end
- Banco de dados
- APIs
- Estrutura do projeto

---

## Casos de uso

- Protótipos rápidos
- MVPs
- Estudos
- Desenvolvimento acelerado
